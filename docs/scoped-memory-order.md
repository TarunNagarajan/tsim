# Scoped memory causality foundation

`include/tsim/scoped_memory_order.hpp` is a standalone per-thread causality and byte-conflict core. It is not yet connected to interpreter accesses. The existing CUDA runtime continues to use its warp-level shared-memory detector; global/cross-CTA race diagnostics and complete visibility semantics remain open. This component supplies the scoped foundation for that integration without treating host execution order as CUDA synchronization.

The [PTX ISA 8.5 memory model](https://docs.nvidia.com/cuda/archive/12.6.3/parallel-thread-execution/index.html#memory-consistency-model) defines scopes, moral strength, observation through RMW chains, release/acquire patterns and fence synchronization. The core uses separate actor identities for individual threads, including device/grid/CTA/cluster membership and an explicit host category. CTA and cluster scope stop at grid boundaries; GPU scope can include other grids on the same device; system scope includes the mathematical host actors. Host atomic interoperability conditions still require separate runtime and hardware validation.

Sparse vector clocks carry causality across caller-provided, unaliased generic-proxy namespaces. Byte histories retain weak accesses separately from each exact-width strong scope class, so stronger operations cannot hide earlier weak races. Strong operations are exempt from race reports only when they overlap completely and both scopes include the other actor, or when program/causality order already relates them. Partial overlap remains a mixed-size conflict.

Every write has a distinct version identity. A caller can supply the actual complete scalar read-from identity; zero denotes initialization. Without an explicit identity, the component uses a complete latest scalar version if present. It does not infer a publication for a fragmented or differently sized read. This convenience selects one observed schedule and does not validate all coherence/causality axioms or enumerate legal weak-memory outcomes. The core carries synchronization metadata, not data values.

Publication endpoints retain the first release's scope, scalar location and clock snapshot. Intervening strong writes and reads have their own scopes. RMW propagation requires each observation link to be morally strong; a relaxed relay carries origins without acquiring their payload. A later acquire or fence checks the original release endpoint against its own final scope. Per-thread release patterns survive intervening writers, while an unrelated plain writer does not inherit someone else's origin. A read-only failed CAS can acquire an observed publication and record a read conflict without replacing the write version. Release and fence snapshots exclude subsequent unsynchronized payload work.

Acq_rel fences participate in release/strong-write and strong-read/acquire patterns. SC fences additionally join earlier mutually scoped SC fences in the selected execution order; an acq_rel fence does not become an SC fence. CTA phases capture each thread's clock at arrival and grant the joined snapshot to explicit waiters. Arrival alone does not acquire completion, post-arrival accesses stay outside that snapshot, and a reused barrier starts a new phase. The caller remains responsible for actual participation/count/retirement validation.

Run `python3 tests/scoped_memory_order_components.py --out .local/scoped-memory-conformance` in the Ubuntu environment. The [recorded proof](scoped-memory-conformance.json) covers 3,616 scope scenarios, 6,888 assertions and 44,544 causal relations compared with an independent reverse-reachability DAG. Its truth tables include same-CTA threads, separate CTAs/clusters/grids/devices and host actors. GCC, Clang and address/undefined-behavior sanitizers pass. Six copied-header mutations compile and are rejected behaviorally: widened CTA scope, acq_rel/SC conflation, a fence snapshot leak, collapsed width patterns, relaxed RMW acquisition and failed-CAS writes. The checked-in header is never mutated by that harness.

Runtime integration now has [typed PTX fence metadata](fence-semantics.md). It must still preserve load/store/atomic scope metadata, identify actual per-thread actors and observed write versions under concurrent workers, and connect CTA lifecycle events. Proxy/alias/asynchronous paths, complete CUDA API synchronization, value/coherence outcomes and resource-bounded lifetime management need additional work. The core intentionally retains versions through its lifetime to support explicit observations of older writes; it currently supplies no reclamation protocol. Passing this analytical proof establishes the component's tested relations, not complete NVIDIA memory replication.
