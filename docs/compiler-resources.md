# NVIDIA compiler resource evidence

`python tsim.py compile-resources RUN_DIRECTORY` compiles the run's verified PTX with the pinned NVIDIA `ptxas`, then cross-checks allocations with NVIDIA `cuobjdump --dump-resource-usage`. It writes `compiler-resources/resources.json`, an input PTX snapshot, the cubin and both producer logs. `--out DIRECTORY` selects a separate artifact directory. This works entirely on the CPU and requires no NVIDIA driver or physical GPU.

The toolkit is CUDA 12.6.3: ptxas V12.6.85 and cuobjdump V12.6.77. Setup downloads cuobjdump through the checksummed NVIDIA redistribution manifest. A100 uses `sm_80`; H100 uses `sm_90`. The original functional compiler target remains `compute_80` PTX. Reports retain tool versions and binary hashes, the exact command, input PTX identity, output hashes and the original functional run exit code. Compiler introspection can inspect a valid compilation even when functional execution fails; it does not turn that run into a passing numerical test. These fields follow NVIDIA's [binary utility resource documentation](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-binary-utilities/index.html#resource-usage-information).

The parser preserves entry register and barrier counts, stack frames, cumulative stack requirements, spill store/load byte counts, local storage, constant banks and shared storage prefixes. Non-entry device function properties remain separate. Registers, constant bank counts and stack requirements must agree between ptxas and cuobjdump. Cubin shared storage is retained separately: the pinned toolkit can include the 1-KiB system reservation in that producer's value. Only observed deltas of zero or 1024 bytes are accepted; the model adds the system reservation once. Unknown fields, incomplete entry records, duplicate records and producer disagreement are refused.

`python tsim.py residency-report RUN_DIRECTORY --compiler-resources DIRECTORY` validates this evidence before using allocated registers, the shared prefix and block barrier count. For the aligned-prefix CUDA reference, the source's four static bytes become a 16-byte allocated prefix; 124 dynamic bytes therefore require 140 user bytes and 1280 bytes after the 1024-byte reservation and 128-byte allocation rounding. Adding the cubin's raw 1040 bytes and another reservation would be incorrect. The PTX-only residency report continues to refuse this case because its event schema does not capture the prefix.

Compiler lowering can remove PTX local arrays, introduce stack/spill operations, change barrier instructions and otherwise alter the instruction stream. Compiler-backed resource ceilings are consequently distinct from the PTX memory and cache replay. Static spill byte counts do not establish dynamic addresses or traffic, and generated cubins are evidence artifacts rather than the simulator's execution path. No measured achieved occupancy, SASS timing or physical GPU differential accuracy is claimed.

`python tsim.py compiler-conformance` executes complete CUDA numerical references on both profiles, compiles their actual PTX, checks shared padding and resource changes, reloads provenance, exercises PTX device functions and rejects altered inputs, cubins, logs, reports and tool versions. A real ptxas compilation failure must remove its prior success marker. A deliberately faulted numerical run remains ineligible for residency despite successful compiler introspection. The register-pressure reference uses launch bounds and volatile loads/stores across a barrier to force actual compiler spills; the local-array reference separately checks stack allocation with zero spills. Static stack and spill statistics follow the [nvcc resource-usage documentation](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-compiler-driver-nvcc/index.html#printing-code-generation-statistics); they do not determine the dynamic memory traffic. The [recorded report](compiler-conformance.json) includes source hashes, compiler tool hashes and per-case resource data.
