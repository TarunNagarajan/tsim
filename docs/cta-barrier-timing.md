# Configured CTA barrier readiness

`execution-report` now consumes complete typed CTA phases alongside register hazards and memory completion. Run a CUDA program with `--events`, then `compile-resources RUN_DIRECTORY`, then `execution-report RUN_DIRECTORY --compiler-resources RUN_DIRECTORY/compiler-resources --config examples/sm_timing.json --memory-config examples/sm_memory.json`. Named and reduction barriers require verified compiler resource allocation for admission. The zero-ID sync/arrive PTX estimate subset remains available without compiler evidence; the `barrier` alias cannot bypass this boundary.

The optional `cta_barrier` timing configuration declares SM-wide release latency, initiation interval and finite in-flight release capacity. The example supplies two cycles, one cycle and sixteen releases, respectively. These are assumptions, not measured NVIDIA values. Older configuration files remain valid for captures without CTA phases; a phase capture with no declared release service is refused.

Each phase joins its actual arrival instructions and missing-warp exit instructions. For each of these warp causes, every earlier modeled memory access is included in the readiness prefix; accesses after a nonblocking arrival are excluded. With staged global service, the prefix waits on actual read responses and L2 store acknowledgements. Otherwise it waits on the configured memory/parameter tokens. Including exited-warp prefixes is a conservative model assumption. A ready phase then competes for the finite SM release port. Every blocking waiter's next selected instruction waits for its own phase's release completion. Nonblocking producers continue, while their next actual arrival at the same ID waits for the previous phase's reset. Independent IDs retain separate causes.

Saved reductions use actual operand stages. Convergence waits do not read ID/count/vote operands. Arrivals consume their inputs and do not write a result. Saved-result collection writes its destinations without rereading predicate votes. Directed `CTA_REDUCTION` edges identify every contributing arrival's actual source lanes and every result destination's lanes. They cross warps only within the captured phase's CTA; ordinary register hazards retain warp ownership. Guard predicates still have path-wide reads.

Release tails hold resident block storage even when a phase has no waiters and all instructions have already retired. Reports distinguish instruction retirement, execution/phase drain and terminal backing writeback. Release port deadlines persist across launches. Per-phase records preserve ID/generation, exact arrival/exit references, prior-memory references, previous reset, waiter gates, placement and ready/start/completion timestamps, with finite-resource peaks and final drains.

The ordering requirement follows NVIDIA's [PTX barrier specification](https://docs.nvidia.com/cuda/archive/12.6.3/parallel-thread-execution/index.html#parallel-synchronization-and-communication-instructions-bar-barrier). Waiting for completion tokens does not implement a data/coherence model or prove memory visibility. The global service still uses abstract cache traffic; shared/local/constant memory has fixed tokens unless separately modeled, and staged shared-bank service is pending. Observed SIMT paths remain fixed. Independent-thread scheduling, full synchronization/scoreboard coverage, scoped consistency and calibrated hardware cycles remain open.

The [execution suite](execution-conformance.json) includes 35 hand-solved CTA timing/operand/resource-boundary references and 87 independently audited CUDA schedules. Its new fixture checks 4,000 host values per run across publication handoffs, nine reused reduction phases and exit-triggered publication, using A100/H100 profiles, three functional schedules and four workers. Separate auditors reconstruct phase memory prefixes, interval capacities, reset/waiter gates and reduction contributor masks from captured children. Mutations remove contributors, alter source/destination lanes or saved answers, and corrupt release timing, memory prefixes, reset causes and capacity peaks. [Recorded CTA timing evidence](cta-timing-conformance.json) also covers the larger nineteen-launch phase fixture and the Windows report CLI with spaces.
