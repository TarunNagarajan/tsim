# Observed register dependencies

Run `python tsim.py dependency-report RUN_DIRECTORY` after an execution recorded with `--events`. The report saves lane-aware register hazards in `register-dependencies.json`; `--out FILE` selects another destination. `python tsim.py dependency-conformance` checks analytical graphs, parser operand roles, collective capture and numerical CUDA references. The recorded [conformance report](dependency-conformance.json) passes 359 checks. This is an input to the developing SM execution model; it does not predict hardware cycles or claim a complete NVIDIA scoreboard.

The stream remains execution-event schema 1, with additive `dependency_schema: 2`. Explicit register keys encode `id * 2 + wide`, with separate declared narrow/wide file capacities. Registers belong to a launch, block, warp and call-frame generation. Reusing a generation for a different function or file layout is rejected. Frame restoration retains the caller's preceding register versions; different callee generations do not alias them.

Ordinary register reads and writes apply to `execution_mask`. A guard predicate is read over `path_mask`, including lanes where the instruction is predicated off. A destination in a predicated-off lane is not a new writer. The reader verifies integer identities, 32-lane mask bounds, execution containment, file capacities, predicate presence and width, and supported implicit resources before updating the graph.

Each issue has `implicit_uses` and `implicit_defs`. `CC.CF` is the only captured implicit resource here. The producer derives these lists from parsed carry-in/carry-out flags; the consumer independently checks them against the preserved instruction. NVIDIA's [PTX 8.5 extended-precision arithmetic specification](https://docs.nvidia.com/cuda/archive/12.6.3/parallel-thread-execution/index.html#extended-precision-integer-arithmetic-instructions) defines the carry/borrow flag accessed by add/subtract/multiply-add carry forms. It is not preserved across calls, so carrying an inferred flag dependency through a call would require additional semantics.

For each resource and lane, the graph maintains the last writer and the outstanding readers. A read depends on its last writer (RAW). A write depends on the previous writer (WAW) and outstanding earlier readers (WAR), then replaces that version. Edges sharing a predecessor, hazard kind and resource combine exact lane masks. Read-modify-write operations never create self edges. Reads without an observed writer remain explicit `live_ins`; the model does not assign them a fabricated ready time. `CC.CF` has its own per-warp, per-lane resource identity.

The input must have verified program/PTX hashes, successful execution and a complete, conserved capture. Every issue's exact instruction spelling and starting line must match the compiled PTX, preserving predication, multiline statements and inline statements while excluding comments. Captured operand keys are engine virtual registers; matching source text does not establish complete operand extraction for every PTX opcode.

Two extraction defects were repaired at their source. Optional unused atomic operands and discarded destinations now omit the `kNoReg` sentinel rather than emitting a fake register read or write. Indirect calls include their actual wide target register. Parsing assigns instruction text before specialized early returns, so warp barriers and conversions retain provenance. An indirect target alone does not capture argument/return slot transfers.

A further operand audit repaired omitted runtime membership masks in vote, reduction, matching and election; all three bit-search inputs; optional mbarrier counts and state tokens; cluster address ranks; sparse tensor metadata; async completion-barrier addresses; and tensor-map replacement values. Independent AST references deliberately populate inactive optional fields to verify that legacy votes/shuffles, ordinary async commits and dense tensor operations do not invent those dependencies. The collector also supplies PTX register analysis and sync-mask folding; fixes are made there rather than added only to the event writer.

The schema-2 graph consumes [executed collective records](collective-events.md) for shuffle, vote, warp reduction and matching. A directed RAW edge keeps `resource` and `lane_mask` for the contributing source, plus `destination_resource` and a single-bit `destination_lane_mask` for the result. Only edges with the same destination lane combine source masks; merging arbitrary source and destination masks could invent lane pairings. Ordinary edges retain their existing fields. All input versions are read before any output is written, including in-place shuffles and several dispatch groups belonging to one issue. Outstanding readers track the actual source lanes for subsequent WAR hazards. The optional shuffle predicate is a result write but has no transferred-data RAW edge.

Parked attempts have `actual_execution_mask: 0` and no destination writes. Collective schema 2 identifies the actual virtual membership register and first selected lane consumed before parking; data and selector operands are not read. Guard predicates retain path-wide reads. Immediate membership produces no virtual register dependency. Only older collective schema 1 sets `conservative_selection_reads: true` and conservatively includes selected explicit operands. Dispatches omit exactly one data-source occurrence from ordinary reads, preserving a repeated register used also as a selector or membership mask. Inactive shuffle sources have explicit `undefined_results`, without a fabricated input producer. Legal `match.all.sync` result sinks preserve dependencies of the surviving predicate or data result; missing source maps remain refused. Buffering child records preserves issue order even when worker completion order interleaves.

Device-call coverage gaps and election remain refused. Complete typed CTA reductions now have staged contributor dependencies. Call ABI transfers, other control transitions, special-register state and complete synchronization readiness require additional modeling. Register hazards do not establish memory dependencies, weak-memory ordering, physical register allocation, pipeline latency or SASS execution. `complete_scoreboard_dependencies` and `hardware_cycles` remain false.

Validation includes 46 ordinary hazard component checks, 28 directed collective references, 26 exact wait/surviving-output references, 43 collective-contract checks and 43 parser/AST operand/syntax references, plus compiled CUDA capture checks. The carry reference checks all eight output words for each of 67 threads against independent host arithmetic, including add, subtract, multiply-add and different even/odd carry writers. Dependency masks and producer identities are checked across A100/H100 profiles and deterministic, random and adversarial schedules. Runtime mask references check every ballot, all/any vote, match, reduction, shuffle and signed-direction bit-search output. An in-place shuffle reference verifies opposite-parity original writers for all 128 lanes with four CPU workers. Delayed constant and variable vote inputs and an immediate-data shuffle verify exact parked membership reads. Legal match result sinks check both agreement and disagreement, with every contributing source attached to the surviving result. Five exact PTX inputs are accepted by pinned NVIDIA ptxas and their compiler artifacts independently revalidated. Numerical indirect calls pass while their ABI graphs remain unsupported. Corrupted register, predicate, implicit-state, frame, launch, source-line and artifact identities are rejected; older streams remain readable for memory analysis but cannot establish schema-2 carry dependencies.

[CTA phase operands](cta-barrier-timing.md) now distinguish convergence parking, actual arrival reads and deferred saved-result writes. Directed `CTA_REDUCTION` edges carry exact contributor and destination masks across warps within the same captured phase. The execution suite independently checks these edges against captured children, including corrupted contributor, lane, answer and operand-stage records. This remains a virtual data graph; data/coherence and complete synchronization/scoreboard semantics remain open.
