# Address transactions and cache components

Run a CUDA program with `--events`, then use `python tsim.py memory-report RUN_DIRECTORY` to generate `memory-transactions.json`. The report requires a successful process, complete launch/stream boundaries, conserved accesses, no truncation or coverage gaps, unchanged compilation artifacts, and the pinned A100/H100 execution profiles. It analyzes observed logical PTX requests. PTX may lower into several SASS instructions; this report does not predict GPU cycles or DRAM traffic.

Global load/store/atomic spans are grouped by issue, resolved memory space and operation. Their union determines the touched 32-byte sectors. Aligned adjacent 32-lane word accesses touch four sectors; shifting them by a word touches five. This rule follows the [CUDA 12.6.3 Best Practices Guide](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-c-best-practices-guide/index.html#coalesced-access-to-global-memory). Requested bytes and sector coverage bytes are separate quantities, and neither implies how many L1TEX processing wavefronts execute.

Shared topology reports distinct words per bank, load broadcasts, write aliases and atomic updates separately; aliases do not establish a deterministic write winner. Scalar aligned 32-bit requests retain the original topology fields. Naturally aligned byte/halfword/64-bit and complete v2/v4 accesses now preserve their actual word spans and byte ownership, with logical bank-work counts that do not predict physical SASS splitting. The component can also preserve 16-byte spans, but validated capture currently accepts only 1/2/4/8-byte elements. Distributed owner bits remain unsupported by the shared timing service. The [shared bank service](shared-bank-service.md) connects these spans to finite queues and instruction completion. Local addresses retain private lane ownership and use an explicit word-striped layout assumption constrained by the public coalescing rule; physical placement and partition hashing remain unverified. Scalar constant reads count distinct requested addresses. Parameter accesses remain logical ABI traffic excluded from physical transaction predictions. These rules and limits follow the [Programming Guide](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-c-programming-guide/index.html#device-memory-accesses).

`SectorCache` is a separately tested component configurable by sets, ways, line width and sector width. It models modulo set indexing and LRU replacement as assumptions, with independent valid and dirty sectors. A tag hit on an absent sector remains a sector miss. It groups each request's sectors by tag, returns dirty eviction identities, supports allocation/no-allocation behavior, and keeps private ownership namespaces distinct. The default 128-byte lines and 32-byte sectors use the [Nsight Compute metric definitions](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html#metrics-guide). The component now also supports a [configurable hierarchy replay](cache-hierarchy.md); no measured NVIDIA associativity, replacement, placement or latency is claimed.

`python tsim.py memory-conformance` checks 53 analytical component cases and 24 CUDA/model integration checks. They cover coalescing, partial/crossing/vector spans, high addresses, shared broadcasts/conflicts/aliases, private local stripes, cache tag/sector validity, LRU, dirty evictions, namespace separation, rejected geometry, real A100/H100 traffic, and rejected incomplete or modified artifacts. The [recorded report](memory-conformance.json) contains 77 passing checks. Full opcode policies are retained and decoded for hierarchy replay; unsupported hints are rejected. Hardware SM placement, residency, pipelines, timing and calibration remain active work.
