# Asynchronous global memory service

`python tsim.py execution-report RUN_DIRECTORY --memory-config examples/sm_memory.json` connects conserved global load/store sectors to the SM scheduler. The [example configuration](../examples/sm_memory.json) declares synthetic cache geometry, LSU/L2/backing ports, latency, queue and miss-entry capacities, and dirty writeback storage. Every parameter has assumption provenance. Ordinary execution-pipeline latency remains configured separately; the fixed memory-token latency is replaced by actual service responses in this mode.

The controller retains the [staged read-service behavior](sector-read-service.md): finite whole-request LSU admission per SM, private L1 caches, a shared L2 input queue and lookup slots, pending miss entries, actual completion-time fills, and duplicate miss merging. Global stores bypass L1 and commit in L2. Store misses fetch sector ownership before modifying L2; this requested-sector ownership read is an explicit conservative assumption independent of byte coverage. Store acknowledgement follows the L2 commit and configured response delay. An acknowledgement does not imply that dirty L2 data has already reached backing storage.

Dirty eviction reserves enough writeback storage for the entire victim before changing cache state. A completed backing read whose replacement cannot reserve that storage remains buffered with its miss entry occupied. Writeback completions release credits and unblock these fills. Dirty packets share the backing initiation port with reads, retain reservations while queued and in flight, and preserve their sector identities. A later backing read of the same sector waits for an already pending dirty version to complete. The backing port is FIFO; bank/row/physical partition scheduling remains open.

The SM scheduler treats a submitted memory instruction's completion as unresolved. RAW and WAW consumers await its actual response; WAR consumers await its operand-read issue time. Finite memory admission can stall a ready warp while other ready warps issue. Memory responses free instruction-pipeline slots, and block resources remain allocated through all instruction completion tails. A block may retire after its store acknowledgements while dirty backing packets remain live. The current cold-cache launch-boundary assumption then drains dirty L2 sectors before the next launch; resident area is zero during that final drain. Pipeline and LSU/L2/backing port deadlines persist across launches, including initiation intervals longer than result latency.

Reports retain memory request identities, actual issue/response times, preserved PTX cache policies, L2 lookup intervals, backing reads, dirty packet reservations/completions, store commits and resource-token histories. A separate verifier sweeps those histories to check LSU, upstream, L2 input/lookup, miss-entry and writeback capacity; matches responses to SM instructions; and audits shared backing bandwidth, dirty-version ordering, and cross-launch port continuity. These checks supplement independently solved schedules rather than using the scheduler as its own timing oracle. [The component report](sector-memory-conformance.json) covers store commits, delayed writebacks, dirty-fill pressure and conservation; [SM execution evidence](execution-conformance.json) adds asynchronous readiness and actual numerical CUDA replay.

Only weak global loads with `.ca`/`.cg` and weak global stores with `.wb`/`.cg` enter this service. Full preserved opcodes are decoded before modeling, with strong/volatile accesses, unknown hints, noncoherent loads and other memory spaces refused. Parameter ABI accesses stay outside physical sector service. [PTX cache operators](https://docs.nvidia.com/cuda/archive/12.6.3/parallel-thread-execution/index.html#cache-operators) describe performance hints and do not change memory consistency. The model does not carry data values or establish L1 coherence or weak-memory outcomes. Existing L1 tag validity is not a claim that globally stored data is coherent there.

This is configured PTX path replay with synthetic requested-sector/LRU/FIFO/ownership/drain assumptions. It is not physical NVIDIA timing calibration, SASS execution, a complete scoreboard, regenerated SIMT control, independent thread scheduling, DRAM bank simulation, or memory-model validation. Atomics, scoped ordering, shared/local/constant service, dynamic spills and async/tensor memory paths remain further work within the full replication goal.
