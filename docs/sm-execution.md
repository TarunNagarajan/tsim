# Configured SM execution

`python tsim.py execution-report RUN_DIRECTORY` replays complete captured PTX warp streams through SM admission, four scheduler partitions, register readiness and finite pipelines. It writes `sm-execution.json`. `--config PATH` loads explicit timing assumptions; [the example configuration](../examples/sm_timing.json) supplies uncalibrated values. `--memory-config examples/sm_memory.json` connects actual global load/store sectors to [staged cache and writeback service](sector-memory-service.md). `--compiler-resources RUN_DIRECTORY/compiler-resources` uses validated ptxas/cuobjdump allocation for admission while preserving PTX estimates and virtual register identities separately.

This layer produces model cycles. Its default latencies, throughput, queue capacities and pipeline sharing are synthetic examples. Configuration requires an assumption description; measurement or published-specification claims are refused until their evidence can be validated. SM capacity constraints use the separately [SDK-verified admission model](sm-residency.md). No physical GPU timing measurement is available on this machine.

Each SM admits blocks in flattened grid order with rotating first-fit placement. Resident warps retain their allocator-assigned partition, including blocks with zero register allocation. Each partition can issue one instruction per model cycle, selecting a ready warp in round-robin order. A rotating partition sweep shares SM-wide ports fairly. Pipeline configuration declares latency, initiation interval, maximum in-flight instructions, and either partition-local or SM-wide scope. Queue capacity includes the entire completion tail; completion frees capacity before the same cycle's admission and issue phases.

Registers are consumed at issue and produced at completion. RAW and WAW predecessors must complete before a dependent instruction issues. WAR predecessors must have consumed their operands; an independent overwrite can complete before a slower earlier instruction. Directed collective lane edges are validated by the dependency graph before becoming warp-instruction readiness constraints. Predicated-off attempts and recorded parked attempts use the configured control pipeline. Branch/return/control attempts complete before the next recorded path instruction can issue. This is replay of observed path selection, rather than generation of a new SIMT schedule or a complete rendezvous scoreboard.

Block resources remain allocated until every issued instruction and CTA release tail completes, even if a return instruction completes ahead of an earlier memory instruction. Timed memory completion stays unresolved until an actual modeled response arrives. Store acknowledgement follows L2 commit; dirty backing packets can remain live after a block retires, and the current cold-cache launch assumption drains them before the next launch. Pipeline, memory-port and CTA release-port deadlines persist across launches. Reports include instruction issue/completion timestamps, placement, block lifetimes, pipeline and memory resource histories/peaks and exact resident warp-cycle integrals. The reported resident fraction divides these integrals by model duration and configured SM capacity. Blocked-probe counters count scheduler inspections, rather than claiming hardware stall-cycle measurements.

`python tsim.py execution-conformance` passes 613 checks, including 52 original scheduler references, 30 asynchronous SM memory references, 29 store/writeback references, 35 CTA readiness/operand references, 85 shared bank/byte/atomic references, 20 common LSU/SM references, 73 global RMW/cache/pin references, 12 atomic SM references and 124 audited schedules from actual numerical CUDA programs across A100/H100 profiles, three source scheduling modes and four CPU workers. Separate interval and resource-token sweeps audit every emitted schedule against hazards, issue bandwidth, port initiation intervals, queue capacity, admission budgets, block retirement and occupancy integrals. Corrupted schedules must fail those independent checks. Tests include unresolved RAW/WAW, WAR read timing, dirty backing tails, zero-register placement, finite miss/writeback queues, shared ports, multiple SMs and cross-launch throughput. Actual cache-policy tests distinguish overlapping miss merges from warm hits with serialized LSU admission. NVIDIA compiler-backed admission is tested without executing generated cubins. [The recorded report](execution-conformance.json) hashes model, reference, capture-writer and patch inputs.

Only explicitly classified instruction families enter this initial layer: selected integer/bit/predicate arithmetic, FP32 arithmetic, conversions, ordinary loads/stores, branches/returns and captured shuffle/vote/reduction/match operations. Unknown register origins, undefined collective sources, conservative legacy parked reads, unsupported instructions, failed/truncated captures and altered provenance are refused. Volatile and ordered memory operations and calls require additional readiness/service semantics and are currently refused. Captured default scalar32/64 shared atomics require the shared service; global atomics require the global memory and atomic configurations. Complete typed CTA phases use the [configured barrier service](cta-barrier-timing.md), including staged reduction dependencies and prior-memory completion. Additional floating arithmetic types need separate declared classes.

Memory instructions occupy fixed-latency tokens unless an explicit memory configuration enables the staged global service. That service models conserved sectors, actual fills, miss merging, finite queues, dirty eviction and launch drains. Local/constant timing service, DRAM bank scheduling, shared data/coherence and weak-memory behavior remain open. Configured shared bank completion is modeled as logical PTX word work. Other open work includes regenerating SIMT paths, full synchronization readiness, independent thread scheduling, complete opcode dependency extraction, physical-register/SASS behavior, dynamic spills, clusters and hardware differential calibration. Passing this layer's checks does not establish complete NVIDIA replication.

`--shared-config examples/sm_shared.json` enables [shared bank completion and common LSU joins](shared-bank-service.md), including actual mixed generic global/shared requests. Shared responses participate in register readiness, CTA pre-arrival memory prefixes and resident tails. [The independent shared proof](shared-bank-conformance.json) covers logical scalar/vector/subword word work, broadcast/alias ownership, finite bank queues, scalar32/64 atomic locks, joined responses and persistent bank/ingress deadlines. These assumptions do not establish physical SASS splitting, data coherence or measured hardware latency.

Configured [global scalar atomic completion](global-atomic-service.md) now conserves every lane RMW, protects cache victims until updates finish, and feeds finite queue/word-lock/response timing into SM and CTA readiness. Its four-launch CUDA fixture checks 6,600 host results per run across both profiles and three schedules with four CPU workers. The timing matrix adds constrained resources and two SMs. L2 placement, pins, unconditional dirtying and latencies remain assumptions; data/coherence, scoped ordering, SASS and physical GPU calibration remain open.
