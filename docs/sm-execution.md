# Configured SM execution

`python tsim.py execution-report RUN_DIRECTORY` replays complete captured PTX warp streams through SM admission, four scheduler partitions, register readiness and finite pipelines. It writes `sm-execution.json`. `--config PATH` loads explicit timing assumptions; [the example configuration](../examples/sm_timing.json) supplies uncalibrated values. `--compiler-resources RUN_DIRECTORY/compiler-resources` uses validated ptxas/cuobjdump allocation for admission while preserving PTX estimates and virtual register identities separately.

This layer produces model cycles. Its default latencies, throughput, queue capacities and pipeline sharing are synthetic examples. Configuration requires an assumption description; measurement or published-specification claims are refused until their evidence can be validated. SM capacity constraints use the separately [SDK-verified admission model](sm-residency.md). No physical GPU timing measurement is available on this machine.

Each SM admits blocks in flattened grid order with rotating first-fit placement. Resident warps retain their allocator-assigned partition, including blocks with zero register allocation. Each partition can issue one instruction per model cycle, selecting a ready warp in round-robin order. A rotating partition sweep shares SM-wide ports fairly. Pipeline configuration declares latency, initiation interval, maximum in-flight instructions, and either partition-local or SM-wide scope. Queue capacity includes the entire completion tail; completion frees capacity before the same cycle's admission and issue phases.

Registers are consumed at issue and produced at completion. RAW and WAW predecessors must complete before a dependent instruction issues. WAR predecessors must have consumed their operands; an independent overwrite can complete before a slower earlier instruction. Directed collective lane edges are validated by the dependency graph before becoming warp-instruction readiness constraints. Predicated-off attempts and recorded parked attempts use the configured control pipeline. Branch/return/control attempts complete before the next recorded path instruction can issue. This is replay of observed path selection, rather than generation of a new SIMT schedule or a complete rendezvous scoreboard.

Block resources remain allocated until every issued instruction completes, even if a return instruction completes ahead of an earlier memory instruction. Reports include instruction issue/completion timestamps, placement, block lifetimes, pipeline occupancy peaks, resident resource peaks and exact resident warp-cycle integrals. The reported resident fraction divides these integrals by model duration and configured SM capacity. Blocked-probe counters count scheduler inspections, rather than claiming hardware stall-cycle measurements.

`python tsim.py execution-conformance` passes 133 checks, including 52 independently solved timing references and 30 audited schedules from actual numerical CUDA programs across A100/H100 profiles, three source scheduling modes and four CPU workers. A separate interval-sweep checker audits every emitted schedule against hazards, issue bandwidth, port initiation intervals, queue capacity, admission budgets, block retirement and occupancy integrals. Corrupted schedules must fail that independent checker. Tests include WAR read timing, retirement tails, zero-register placement, shared ports, multiple SMs and successive launches. NVIDIA compiler-backed admission is tested without executing generated cubins. [The recorded report](execution-conformance.json) hashes model, reference, capture-writer and patch inputs.

Only explicitly classified instruction families enter this initial layer: selected integer/bit/predicate arithmetic, FP32 arithmetic, conversions, ordinary loads/stores, branches/returns and captured shuffle/vote/reduction/match operations. Unknown register origins, undefined collective sources, conservative legacy parked reads, unsupported instructions, failed/truncated captures and altered provenance are refused. Volatile and ordered memory operations, atomics, calls and block barriers require additional readiness/service semantics and are currently refused. Additional floating arithmetic types need separate declared classes.

Memory instructions currently occupy configured fixed-latency instruction tokens. Transaction splitting, shared-bank service, cache fills, miss queues, DRAM scheduling, data/coherence and weak-memory behavior are not yet integrated. Other open work includes regenerating SIMT paths, full synchronization readiness, independent thread scheduling, complete opcode dependency extraction, physical-register/SASS behavior, dynamic spills, clusters and hardware differential calibration. Passing this layer's checks does not establish complete NVIDIA replication.
