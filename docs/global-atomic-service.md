# Global scalar atomic service

`execution-report RUN_DIRECTORY --memory-config examples/sm_memory.json --atomic-config examples/sm_atomic.json` enables scalar global atomic completion. Add `--shared-config examples/sm_shared.json` for kernels that also access shared memory, including mixed generic instructions. The atomic configuration requires the global memory configuration. Compiler resource evidence remains available through `--compiler-resources PATH`.

The [CUDA 12.6.3 programming guide](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-c-programming-guide/index.html#atomic-functions) specifies atomic read-modify-write operations and distinguishes device, block and system scope. Its traditional unsuffixed atomic APIs have relaxed ordering and device scope. The modeled timing subset accepts captured, naturally aligned scalar 32/64-bit default global/generic `atom` and `red` forms. Explicit scope, acquire/release ordering, vector and 128-bit atomics need additional models. Supported opcode spelling is checked before admission; functional support and timing support have separate boundaries.

Each captured lane remains a distinct RMW job with its original address and width. A request bypasses private L1 and uses the existing sector lookup, miss merging, fill and backing service. Lanes addressing one sector share its availability event; their updates are never merged. Cache-ready jobs enter a finite FIFO and reserve finite completion slots through one initiation port. Overlapping four-byte words remain locked until RMW completion across all modeled SMs; a 64-bit update reserves both words together. FIFO arbitration and this mixed-width exclusion are conservative model choices, not a measured NVIDIA implementation.

An available sector pins its L2 line until its last atomic update commits. A fill whose selected LRU victim is pinned waits while retaining its miss reservation. Feeding only cache-ready jobs into the RMW FIFO prevents an unavailable head from blocking updates needed to release a victim. Completion dirties the sector conservatively, including failed CAS and operations that leave its value unchanged, because the timing service does not carry values. Dirty eviction, terminal writeback and backing-port tails use the existing global service. A sector response follows its last RMW plus response transmission; the instruction and common LSU reservation wait for every sector and any shared fragment. RAW/WAW readiness, CTA pre-arrival memory prefixes and resident retirement use that joined response. Cross-launch atomic initiation deadlines persist while caches start cold.

Reports expose exact byte jobs, lookup outcomes, successful fills, word exclusion intervals, pin lifetimes and separate upstream/FIFO/active resource ledgers. The upstream ledger includes cache-unready jobs; the live snapshot's `atomic_upstream` counts cache-ready jobs awaiting FIFO admission. Independent references reconstruct lane jobs from captured bytes, audit finite storage, FIFO handoffs, port deadlines, overlapping locks, response joins and protected victims, and reject corrupted records. Availability checks compare against recorded lookup outcomes and successful fills; they do not independently reconstruct every cache replacement decision.

`tests/conformance/global_atomic_timing.cu` performs 6,600 host comparisons over four launches per run. It checks contended 32/64-bit ticket returns, per-word updates, mixed global/shared generic atomics, reduction forms, successful/failed CAS, min/max/exchange/bitwise/inc/dec results and CTA handoffs. The source matrix uses four CPU workers, both profiles and three schedules. Timing audits add default, constrained finite-resource and two-SM configurations. [The atomic proof](global-atomic-conformance.json) records these checks and hashes; [the broader execution report](execution-conformance.json) records regressions.

Functional values are checked by the CPU interpreter and host references. Timing carries no data values, coherence or scoped weak-memory outcomes. Ordinary loads/stores following atomics may have independent timing unless register or CTA dependencies connect them; read-own-write forwarding is not established. L2 placement, queue dimensions, arbitration, pinning, unconditional dirtying and all latencies are declared assumptions. Physical SASS lowering, NVIDIA cycle equivalence and hardware differential validation remain open.
