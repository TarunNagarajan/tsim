# Staged sector-read service

`scripts/sector_read_service.py` implements an asynchronous read-service component for future integration with the [SM scheduler](sm-execution.md). `SectorReadService.submit()` attempts whole-request admission at the current model cycle. `advance()` returns completed request identities and timestamps; `next_wakeup()` identifies the next event; `drain()` checks that every queue and reservation is released. SM execution reports currently continue to use fixed-latency memory tokens; this component has not yet replaced those tokens.

The component has one configured LSU admission port and finite outstanding request slots per SM, private read-only L1 caches, a shared read-only L2 cache, a finite L2 input queue, finite lookup slots and a finite table of pending backing misses. A request's bounded sector fanout remains upstream when the input queue is full. A lookup waiting for a miss entry retains its lookup slot and applies backpressure. Later same-sector misses merge with the pending transaction. Miss credits freed at completion go to older blocked lookups before new same-cycle lookup completions can consume them.

Lookups classify cache state at their completion time. Pending backing data cannot become an L2 hit before backing completion, and an L1 fill becomes valid only when the response reaches its requesting SM. Same-cycle fills precede lookups. Requested-sector fills, clean LRU replacement, modulo indexing, staged latencies, service-port initiation intervals and all queue capacities are explicit synthetic assumptions. The backing port supports pipelined reads with finite miss entries, rather than modeling DRAM banks, row activation or NVIDIA physical partition hashes.

The [component evidence](sector-read-conformance.json) records independent timing references for cold and warm paths, L1 bypass, sector validity, cross-SM miss merging, delayed fills, conflict eviction, lookup/queue/miss backpressure, same-cycle credit arbitration, request retries and conservation. A mixed-width forty-request workload has an independent one-backing-read-per-unique-sector oracle. The command `python tests/sector_read_components.py --out .local/sector-read-conformance` runs these checks without a GPU or CUDA compiler.

This initial component accepts read-only global sector identities with optional L1 bypass. It has no data values, stores/writebacks, atomics, memory consistency/coherence, local/shared/constant service or calibrated hardware timing. These need explicit additional semantics, along with integration of unresolved memory completions into SM hazard and block-lifetime readiness. The complete NVIDIA replication goal remains open.
