# Configurable sector-cache replay

`python tsim.py cache-report RUN_DIRECTORY` writes `cache-hierarchy.json` from a complete conserved capture. `--profile profiles/synthetic-cache.json` supplies explicit geometry and replay rules. The default profile is the same synthetic example: one modeled SM, a 64-set four-way L1, a 256-set eight-way shared L2, 128-byte lines and 32-byte sectors. Geometry, modulo indexing, LRU, placement and all traffic rules are model assumptions. This profile is not a calibrated A100 or H100 microarchitecture.

The functional parser retains full instruction text even when its execution AST drops cache hints. The replay decoder reads that preserved opcode, including predicate prefixes, cache operators, memory ordering, scope, noncoherent qualification and L1/L2 hints. Before replay, captured memory statements must match the hash-verified compiled PTX at their source line; inline statements and multiline vectors are supported. Unsupported hints cannot silently become the default cache policy. Cache operators are performance hints and do not alter functional memory consistency, as specified in [PTX ISA 8.5](https://docs.nvidia.com/cuda/archive/12.6.3/parallel-thread-execution/index.html#cache-operators).

Default and `.ca` loads visit the selected private L1, then send its missing sectors to shared L2. `.cg` loads bypass L1. Default `.wb` and `.cg` global stores visit L2 and bypass global L1; local `.wb` stores use a private ownership namespace and write back from L1. Scalar relaxed global atomics visit L2 as one sector-state RMW request; lane atomic updates remain separately counted in the transaction report. No functional data values or coherence protocol are replayed. Loads through a stale global L1 line are counted as state hits without claiming a returned value.

Each cache tracks tag presence, sector validity and sector dirtiness separately. Only requested sectors fill. Every missing read or store sector fetches from the modeled backing memory; read-for-ownership on store misses is an explicit assumption even for a full-sector store. Dirty L1 evictions route to L2, and dirty L2 evictions route to backing writes. Reports separate demand hit/miss traffic, bypass traffic, eviction writebacks and terminal drains. At each launch boundary, the model drains dirty L1 sectors through L2, drains L2 to backing memory, and begins the next launch cold. These drains are assumptions, not claims about CUDA kernel-end flushing.

Replay follows captured completion order. CTA placement uses the flattened block index modulo the configured SM count. Local ownership is scoped to launch/block/warp with lane-word stripes; its physical placement and set collisions remain synthetic. Residency, concurrent cache queues, instruction lowering, cache partitions, measured DRAM traffic and GPU cycles are not modeled. Shared, constant and parameter traffic remains in the separate address transaction report. `.cs`, `.lu`, `.cv`, `.wt`, `.nc`, eviction/prefetch/cache-policy hints, volatile and strong ordered accesses are decoded and rejected by this hierarchy until their required behavior is implemented. System-address provenance is unavailable.

`python tsim.py cache-conformance` checks analytical cold/warm reuse, private L1/shared L2 behavior, tag hits with missing sector data, conflict/capacity eviction, dirty propagation, local owner separation, atomics, policy rejection and geometry validation. Actual CUDA cases verify retained `.ca`/`.cg` instructions and exact 20-sector traffic, an eviction hint that survives functional parsing but refuses unsupported replay, four-worker vector traffic, three independent launch boundaries, modified-policy rejection and incomplete/fault/gap rejection. The recorded report is [cache-conformance.json](cache-conformance.json). Hardware differential calibration remains unavailable.
