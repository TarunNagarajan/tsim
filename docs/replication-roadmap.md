# NVIDIA replication program

The goal is a progressively comprehensive NVIDIA CUDA execution and GPU architecture simulator on a CPU. A passing demonstration is a milestone, not completion of this program. Original execution code remains attributed to the pinned PantheonSim engine; tsim's changes are independently tracked and verified.

The initial functional baseline compiles CUDA 12.6.3 source into compute_80 PTX, runs 16 integration checks, and records actual interpreter warp state. It has no hardware timing model. Upstream capability claims are leads for verification, not automatically claims about this build.

The implementation tracks are:

| Track | Required behavior | Evidence required |
| --- | --- | --- |
| CUDA/PTX conformance | Typed arithmetic, conversions, calls, control flow, memory spaces, collectives, atomics and supported API behavior | Independent references, boundary cases, schedule variants, explicit failures for unsupported behavior |
| SIMT and synchronization | Per-thread control flow and state, warp participation, block/cluster/grid barriers and forward progress | Valid divergent synchronization tests; invalid participation diagnostics; adversarial schedules |
| Memory consistency | Scoped acquire/release, fences, atomicity, ordered communication, memory lifetime and access checks | PTX memory-model litmus tests and race diagnostics; documented legal outcomes |
| Architecture events | Actual per-lane memory addresses and widths, register dependencies, resource requirements, block/warp identity | Trace alignment and conservation invariants; checks against interpreter counters |
| SM model | Block placement, residency, warp schedulers, scoreboards, execution pipelines and contention | Small analytically solvable workloads and published architectural constraints |
| Memory hierarchy | Coalescing, sectors, shared-memory banks, configurable L1/L2, misses and memory queues | Address-pattern microbenchmarks with exact transaction references |
| Timing and calibration | Explicit latency/throughput parameters, cycle simulation and calibration provenance | Hardware measurements where available; predicted-versus-measured error distributions |
| Debugging and differential validation | State inspection, repeatable replay, failure minimization, hardware comparison | Reproducible artifacts; identical functional checks on simulator and physical GPUs |
| Compatibility inventory | Versioned supported/tested/unverified/unsupported states | Machine-readable manifests linked to executed checks; no inferred blanket compatibility score |

PTX behavior follows the [PTX ISA 8.5 specification](https://docs.nvidia.com/cuda/archive/12.6.3/parallel-thread-execution/index.html) corresponding to the local compiler, with later ISA versions tracked separately. Architecture constraints begin with the [Ampere tuning guide](https://docs.nvidia.com/cuda/archive/12.6.3/ampere-tuning-guide/index.html). Parameters from public specifications, measured hardware, and model assumptions must carry separate provenance. A modeled cycle is not automatically a measured NVIDIA cycle.

The expanded functional baseline now passes 343 upstream core checks and 78 CUDA source cases across two profiles and three schedules. Shared-memory publication and counted barriers have a warp-level happens-before detector with explicit limits. The compatibility inventory ties each tested subset to executed checks. [Execution events](execution-events.md) now capture actual scalar/vector load/store addresses, scalar atomics, typed register operands and launch resources with 58 analytical checks. Async/tensor/call paths expose coverage gaps, and complete scoreboard dependencies remain open. The address transaction model now passes 77 analytical and CUDA integration checks for global sectors, shared banks, local stripes, constant requests and a standalone sector-valid cache. A configurable private-L1/shared-L2 cache replay now passes 76 policy, traffic and provenance checks. SM resource ceilings and an admission allocator now pass 61 checks and 3872 comparisons against NVIDIA's standalone SDK occupancy calculator, including Hopper barrier limits. [Compiler resource evidence](compiler-resources.md) passes 91 checks using actual pinned ptxas/cuobjdump allocations, aligned shared prefixes, real spills, separate nonspill stack storage and artifact provenance. Compiler-backed residency preserves the original PTX estimates rather than equating them with allocated registers. The initial [SM execution layer](sm-execution.md) now integrates admission, explicit warp placement, observed hazards and finite pipelines, verified by hand-solved schedules and independent interval audits of actual CUDA captures. Latency, throughput and queue sharing remain explicit uncalibrated assumptions. Optional staged global load/store service now connects actual sectors, completion-time fills, merged misses, finite queues, dirty eviction and backing tails to SM readiness. The layer passes 238 checks and 62 independent CUDA schedule audits; cross-launch pipeline and memory-port deadlines persist. Complete scoreboard/control readiness, other spaces and memory consistency remain open. An instruction name alone cannot establish cache activity.

The [observed dependency model](register-dependencies.md) now passes 359 checks for lane-aware RAW/WAR/WAW hazards, predicate reads over the path mask, virtual file/frame identities and implicit carry/borrow state. Its 43 operand-role/syntax references cover repaired membership, bit-search, mbarrier, cluster, sparse tensor and async completion operands. Compiled carry references preserve different lane writers across two profiles and three schedules; disjoint runtime membership groups pass complete numerical references. Actual collective capture now preserves dispatch groups, waits and source-lane mappings after rendezvous, including four-worker ownership. The graph now consumes these maps with directed source/destination lane identities and old-version snapshots for in-place results; 28 independent component references and a four-worker CUDA parity-writer test verify the behavior. Collective schema 2 now records the precise first-lane virtual membership read before parking, verified against runtime membership with constant/variable CUDA vote inputs and immediate shuffle data. Legal match.all result sinks preserve the surviving output and its contributor dependencies; five exact PTX inputs also pass pinned NVIDIA assembler checks. Legacy schema-1 selection reads remain explicitly conservative. Calls still require ABI argument/return transfers; synchronization and control transitions need explicit readiness semantics. Full opcode operand coverage also remains to be audited. Complete memory capture is not complete scoreboard coverage. The SM scheduler now combines the tested dependency subset with admission, declared warp placement and configurable pipeline readiness. Staged global queues and cache/writeback service now drive actual memory completion readiness. Next work extends explicit control/synchronization readiness, other memory spaces, scoped ordering and dependency coverage. Timing remains an assumption until hardware differential calibration exists.

The broad goal stays active while these tracks remain incomplete. Exact equivalence to undisclosed proprietary microarchitecture cannot be established solely from public documentation. Hardware differential results are currently unavailable on this CPU-only machine and must be reported as unverified.
